# Анализ сейсмических событий

## Состав отчёта

В исходном PBIX одна страница «Страница 3»: столбчатая диаграмма средней глубины по магнитуде, линия количества событий по годам, круговая диаграмма по типам, диаграмма рассеяния средних величин, карта координат, две карточки и срез. Определения визуализаций сохранены в `report-definition/`, компактный список — в `visuals.json`.

Сохранённые DAX-запросы демонстрируют `EVALUATE`, `COUNTROWS`, `ADDCOLUMNS` и `RELATED`. TMDL-скрипты описывают справочник Researchers и связь с EarthquakeResearch. Наличие сохранённого скрипта само по себе не подтверждает, что он был применён к текущей бинарной модели.

## Проверка исходного CSV

Найденный рядом исходный файл содержит 23 412 строк и столько же уникальных ID, период 02.01.1965–30.12.2016. Даты разобраны как MM/DD/YYYY, а отдельные ISO-записи — вторым проходом; неразобранных дат нет. В ключевых полях Magnitude, Depth, Latitude, Longitude пропусков нет.

Содержательные наблюдения:

1. 23 232 записи — Earthquake, ещё 180 — другие типы. Для показателя именно землетрясений нужен фильтр Type.
2. Магнитуда лежит в диапазоне 5,5–9,1. Набор не описывает все слабые события; выводы за его пределы не переносятся.
3. Медиана глубины — 33 км, среднее — около 70,77 км: среднее заметно смещено глубокими событиями. Полезно показывать обе величины.
4. Максимум количества записей — 713 в 2011 году. Число записей зависит от отбора и регистрации; это не прогноз и не доказательство причинного тренда.

## Уточнения для отчёта

В визуализациях есть мера «Число землетрясений», но её выражение из бинарной модели не извлечено. Нужно проверить, что она фильтрует Type, либо переименовать её в «Число событий». Ниже предлагаемые явные определения, а не утверждение об уже сохранённых формулах:

```dax
Число событий = DISTINCTCOUNT('database'[ID])
Число землетрясений =
    CALCULATE(DISTINCTCOUNT('database'[ID]), 'database'[Type] = "Earthquake")
Средняя глубина = AVERAGE('database'[Depth])
Медианная глубина = MEDIAN('database'[Depth])
```

В фактической модели ключ может называться EventID: в определениях отчёта встречается это имя, тогда как в сыром CSV — ID. Перед добавлением мер следует выбрать реальное имя колонки, не создавать второй ключ без необходимости.

Текущая диаграмма рассеяния использует иерархию даты и средние глубину/магнитуду. Её точка может представлять год, а не отдельное событие. Для анализа отдельных событий нужен ID в детализации. Средняя магнитуда — описательная статистика логарифмической шкалы, не средняя энергия.

## Открытие

Открыть `earthquakes.pbix` в Power BI Desktop. Для обновления заменить путь CSV в Power Query на свой. Исходный отчёт не был пересохранён через Desktop; дополнительные проверки находятся в `../results/`. Публичная страница DataLens проверена на доступность и заголовок «ЛР1 дашборд»; формулы её отдельных графиков не извлекались.
